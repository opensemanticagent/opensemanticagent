Does OSA work with legacy systems?

Yes. Your apps don't need AI, a new SDK or a rewrite. They publish a small JSON event onto the message system you already run, and OSA does the rest beside them.

Requests go around the bus

A user waiting on "pay this invoice" still calls the service directly. Only after the work is done does the service publish what happened.

So an OSA outage never blocks a customer.

What a legacy app sends4 / 8

One JSON envelope. Any language.

No SDK needed: build the JSON, put it on the transport. Check it against the published JSON Schema.

{ "spec": "osa/0.5", "id": "erp-7781-20261123-0042", "topic": "order.placed", "source": "svc://erp/orders", "time": "2026-11-23T09:41:00Z", "hints": { "strict": true }, "data": { "order": "SO-7781", "total": 412.50 } }
A stable id

Made once, so resends are delivered once.

A plain topic

Subscribers match it for free, no model.

No AI unless you want it5 / 8

Structured events stay at the free check

1  Topic match, free

Plain patterns on topic names. Legacy events stop here.

2  Similarity, cheap

Only for subscribers who ask by meaning, such as "anything about late deliveries".

3  AI judge, only when unsure

Under a token budget. Most useful for free text: tickets, reviews, notes.

strict: true means no model, ever

Use it for payments, safety alarms and anything regulated.

Operations7 / 8

Alerts that reach a person, with what to do

Alert

alert.batch.failed · critical

Nightly invoice batch failed 3 times. One open condition per key, so 40 retries become one alert.

Recommendation

recommendation.batch.failed

Re-run from the last good checkpoint. Effort: low. Can be undone: yes.

Notification

The on-call phone gets one push with the top action, even in quiet hours because it is critical. No answer in 10 minutes: the backup is told.

Outcome

"Did this" or "not useful", tapped on the phone, goes back on the bus, so the advice gets better over time.

Start small8 / 8

A legacy rollout in three steps

1. Publish

Pick one system. Emit envelopes for events it already logs.

2. Subscribe by topic

Route at the free check. No model, no budget. Add phone notifications for the alerts that matter.

3. Add meaning where text is

Turn on similarity and the judge only for tickets, notes and reviews.

Today the repo has the spec, JSON Schemas, test vectors and an MCP server. Client libraries are welcome contributions.
