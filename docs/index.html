Messages delivered by meaning

Open Semantic Agent (OSA) is an open spec for publish/subscribe that routes each message by what it is about, not only by its topic. It runs the free and cheap checks first and calls an AI model only when they are unsure, under a budget you set.

Read the spec GitHub

How a message is routed

CHECK 1 · FREETopic matchPlain topic patterns, in microseconds. Most traffic stops here.
CHECK 2 · CHEAPSimilarityEmbeddings compare the message with what each subscriber said it wants.
CHECK 3 · PAIDAI judgeOnly for the unsure cases, with token budgets and a skip rule when they run out.

Every decision writes an audit record you can explain and replay. Topics marked strict never reach a model.

Implement it

The spec defines the message envelope, the subscription manifest, the three-check decision engine, audit records, and the agent interfaces (MCP tools, HTTP, Server-Sent Events, WebSocket and A2A). JSON Schemas and routing test vectors let you check an implementation against it.

Your AI assistant can read the spec and check documents against the schemas through a small MCP server:

uvx open-semantic-agent

What it adds to a broker

Conventional broker Open Semantic Agent
String topics Semantic subscriptions: subscribe by meaning
Payload delivered as-is Schema mediation: each subscriber gets its own contract
Dedupe by message ID Semantic dedupe: 40 alerts about one incident become 1
Static priority Reasoned urgency, with a recorded rationale
Slow consumer → lag or drop Backlog summarization: a digest instead of a loss
Dead-letter queue Self-healing DLQ: diagnose, repair, retry or escalate
Replay the raw log Briefings: "catch me up on order 123 since Monday"
One reply Consensus fan-in: ask N agents, reconcile the answers
Per-topic ACLs Per-subscriber redaction by clearance
Opaque routing Every decision audited and replayable
